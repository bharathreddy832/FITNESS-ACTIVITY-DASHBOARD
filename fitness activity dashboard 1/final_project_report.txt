2. ABSTRACT & INTRODUCTION
--------------------------------------------------------------------------------
Project Overview:
FitPulse is a full-stack MERN (MongoDB, Express.js, React, Node.js) web application 
designed to empower users to record, track, and visualize their daily fitness 
activities. By combining streamlined workout logging with interactive charts, 
FitPulse turns raw exercise statistics into actionable health insights.

Problem Background:
In today's fast-paced digital environment, maintaining consistent physical fitness 
routines is challenging. Many individuals struggle because their fitness data is 
either fragmented across multiple wearable devices or recorded in unstructured logs 
that lack intuitive visualization. Without clear tracking of caloric expenditure, 
duration, and exercise distribution, users often lose motivation and fail to 
evaluate their long-term progress effectively.

Proposed Solution:
FitPulse provides a centralized, high-performance dashboard that allows users to 
instantly log exercises, filter workout history by discipline (Running, Weightlifting, 
Cycling, Yoga, etc.), and monitor progress through dynamic analytics charts powered 
by Chart.js. The application ensures persistent tracking, responsive layout 
compatibility, and a sleek dark/light mode experience.

Purpose of the Project:
The primary objective of this project is to demonstrate full-stack web development 
proficiency by building a scalable, responsive, and user-centric health dashboard 
adhering to modern software engineering best practices.


3. PROBLEM STATEMENT, OBJECTIVES & SCOPE
--------------------------------------------------------------------------------
Problem Statement:
"How might we design a unified digital platform that simplifies workout logging and 
transforms complex fitness datasets into transparent, motivating visual metrics 
for everyday athletes?"

Project Objectives:
  1. Seamless Data Recording: Enable users to log workout types, active durations, 
     calories burned, dates, and personal notes effortlessly.
  2. Interactive Visual Analytics: Implement real-time graphical representations 
     of chronological caloric burn and duration distribution across different disciplines.
  3. Data Filtering & Retrieval: Provide instant client-side and server-side filtering 
     mechanisms to examine specific training categories.
  4. Reliable Persistence: Guarantee robust data storage and retrieval using local 
     persistence fallback and MongoDB integration.

Project Scope:
  - In-Scope: Workout CRUD operations, dynamic charting with Chart.js, responsive 
    Tailwind CSS interface, filterable history logs, and session persistence.
  - Out-of-Scope: Direct real-time synchronization with physical smartwatches 
    (e.g., Apple Watch, Garmin APIs) and live GPS route mapping.

Target Users:
  - Fitness enthusiasts and athletes wanting to track workout metrics.
  - Personal trainers monitoring routine consistency.
  - Casual individuals seeking an intuitive tool to build healthy exercise habits.


4. FEATURES & FUNCTIONAL REQUIREMENTS
--------------------------------------------------------------------------------
Main Features:
  - Interactive Dashboard KPIs: Total workouts count, cumulative calories burned, 
    active training hours, and average burn rate per workout.
  - Graphical Charts:
      * Line Chart: Calories Burned Over Time.

  - Read: Retrieve and display historical logs and aggregated summary statistics.
  - Update: Modify existing workout details (supported architecturally via backend API).

Authentication & Validation:
  - Client-side validation ensuring mandatory numerical inputs for duration and caloric burn.
  - Form restrictions preventing negative or zero-value inputs.

System Requirements:
  - Frontend: React 18+, Tailwind CSS, Chart.js, Lucide Icons.

5. ALGORITHMS & METHODOLOGY
--------------------------------------------------------------------------------
System Workflow:
  1. User authenticates and loads the FitPulse dashboard.
  2. React state initializes by fetching existing workout records from local 
     storage or the MongoDB backend.
  3. Aggregate metrics (total duration, total calories) are computed using functional 
     array reduce methods.
  4. Chart.js instances render visual canvas elements based on sorted chronological 
     date arrays.
  5. User actions (Add/Delete/Filter) trigger immediate state updates and re-render 
     components reactively.

Algorithms Used:
  - Data Aggregation Algorithm: Computes total calories and hours by iterating through 
    workout arrays using functional reduction.
  - Chronological Sorting Algorithm: Sorts workout datasets by date strings to ensure 
    correct time-series progression on line charts.

Development Methodology:
  - Agile Iterative Model: Developed in sprints focusing first on core UI components, 
    followed by state management, charting integration, and backend API integration.

Data Flow:
  User Input -> React Form State -> Event Handler -> State Array Mutation -> 
  LocalStorage / MongoDB Persistence -> Chart & UI Re-render.


6. TECHNOLOGIES & IMPLEMENTATION
--------------------------------------------------------------------------------
Frontend Technologies:
  - React.js: Component-based UI architecture.
  - Tailwind CSS: Utility-first styling framework for responsive design.
  - Chart.js: Canvas-based charting library for data visualization.
  - Lucide React: Modern SVG icon set.

Backend Technologies:
  - Node.js: JavaScript runtime environment for server-side logic.
  - Express.js: Web framework for building RESTful API endpoints.

Database:
  - MongoDB: NoSQL document database storing workout schemas with fields: id, type, 
    duration, calories, date, and notes.

Tools & APIs:
  - Git & GitHub: Version control and source code management.
  - REST APIs: HTTP GET, POST, PUT, DELETE methods for resource handling.

Implementation Details:
  The application is structured around a single-page React architecture where state 
  is lifted to manage workouts globally. Chart instances are managed via React useRef 
  hooks to ensure proper canvas cleanup and memory leak prevention during re-renders.
